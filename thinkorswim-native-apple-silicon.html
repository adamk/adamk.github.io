How to Run Thinkorswim Natively on Apple Silicon Macs

Last verified August 26, 2026 · practical macOS guide

What this solves

Thinkorswim's macOS app contains an Intel install4j launcher stub. Opening the app normally starts through that Intel/Rosetta path. This procedure creates a small shell script that supplies an ARM64 Azul Zulu 17 Java home. In the verified setup, Thinkorswim then hands off to its bundled java-arm runtime and ARM-specific components.

The key difference: clicking the app is the normal Intel-launcher path; running the script supplies the ARM64 Java override used for the native path. The script does not replace files inside Thinkorswim or disable macOS security.

Prerequisites

  • An Apple Silicon Mac (M1 or newer).
  • macOS 14 Sonoma or newer, which is Schwab's current published minimum.
  • Administrator approval for the official installer.
  • A current Thinkorswim installer from Charles Schwab's download page.
  • The ARM64 build of Azul Zulu JDK 17 from Azul's official download page.

Apple Silicon vs. Intel

Check the Mac's CPU architecture:

uname -m

arm64 means Apple Silicon. x86_64 means Intel. Stop here on an Intel Mac: install and launch Thinkorswim normally, and do not install an ARM JDK or use this script.

“Native” here means the long-running Thinkorswim Java process and architecture-specific browser/media components run as ARM64. The outer JavaApplicationStub remains Intel-only and may briefly use Rosetta while handing off to the ARM process.

Step-by-step installation

  1. Install Thinkorswim from Schwab. Open the official download page, choose the Mac installer, and follow its prompts.
  2. Keep the standard location. This guide assumes /Applications/thinkorswim/thinkorswim.app.
  3. Open it once normally. Let Thinkorswim finish updating, then quit it completely. This initializes the installation before adding the launcher.
  4. Install ARM64 Zulu JDK 17. On Azul's download page, select Java 17 LTS, macOS, ARM 64-bit, and JDK. Install the signed DMG using its standard location.

Required Java/JDK setup

Confirm macOS can find ARM64 Java 17. -F makes the command fail instead of silently selecting an incompatible default:

/usr/libexec/java_home -V
ARM_JAVA_HOME=$(/usr/libexec/java_home -F -v 17 -a arm64)
echo "$ARM_JAVA_HOME"
file "$ARM_JAVA_HOME/bin/java"
"$ARM_JAVA_HOME/bin/java" -version

The result should identify Zulu 17 and arm64, or a universal binary that contains arm64. The original working script used /Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home. Resolving it dynamically avoids baking a machine-specific JDK name into the public guide.

Create the native launcher script

Create the file:

nano ~/tos-native.sh

Paste this script:

#!/bin/bash
set -e

TOS_DIR="/Applications/thinkorswim"
ARM_JAVA_HOME=$(/usr/libexec/java_home -F -v 17 -a arm64)

export INSTALL4J_JAVA_HOME_OVERRIDE="$ARM_JAVA_HOME"
export JAVA_HOME="$ARM_JAVA_HOME"

cd "$TOS_DIR"
open ./thinkorswim.app

Press Control-O, Return, then Control-X. Make it executable only by your user:

chmod 700 ~/tos-native.sh

INSTALL4J_JAVA_HOME_OVERRIDE tells the install4j launcher which Java home to use. JAVA_HOME gives child processes the same ARM64 JDK. cd makes the relative app path work, and open starts the app with those variables in its launch environment.

The override is not global. It applies only to this launch. The script does not edit the app bundle, replace its JRE, or change Gatekeeper.

How to launch it

Quit any running Thinkorswim process, then run:

~/tos-native.sh

Use the script for the native path. Clicking the Thinkorswim app icon uses the ordinary Intel install4j path without these Java overrides.

How to verify native ARM64 execution

After launching with the script, verify the bundled runtime and active process:

TOS_JAVA="/Applications/thinkorswim/.install4j/jre.bundle/Contents/Home/bin/java-arm"
test -x "$TOS_JAVA" && "$TOS_JAVA" -version
grep -E 'JAVA_VERSION|OS_ARCH' \
  "/Applications/thinkorswim/.install4j/jre.bundle/Contents/Home/release"
file "$TOS_JAVA"
"$TOS_JAVA" -Xinternalversion 2>&1 | head -1
pgrep -f "$TOS_JAVA" | head -1 | xargs -I{} ps -p {} -o comm=

On the verified machine, this reports bundled Zulu 21.0.5, OS_ARCH="aarch64", a Mach-O arm64 executable, and a live process path ending in java-arm. The live classpath also selects ARM BookMap, JxBrowser, and VLC components. Version numbers may change after updates.

Do not rely only on Finder's “Kind” field for the outer app. The install4j stub and the actual Java process are separate executables. Verify the running Java path shown above.

Troubleshooting

The java-arm file is missing
Quit Thinkorswim and download a fresh current Mac installer from Schwab. Do not copy a JRE from another Mac.
macOS blocks the installer
Confirm it came directly from Schwab. Use the normal Privacy & Security approval flow if macOS offers it. Do not run broad xattr, spctl, or code-signing commands.
Thinkorswim launches, but verification shows an Intel Java process
Quit Thinkorswim completely and relaunch only with ~/tos-native.sh. Confirm the script resolves an ARM64 Java 17 home and that no older process remained open.
java_home reports no matching JVM
The ARM64 Zulu JDK 17 is missing or the wrong architecture/version was installed. Recheck the Azul download selections; do not remove -F to hide the mismatch.
The platform runs out of memory
Use the memory setting available from the Thinkorswim login window rather than editing generated VM-option files by hand.
The app opens from its icon but not the script
Run the Java checks again and confirm Thinkorswim is installed at /Applications/thinkorswim. If you chose another location, update only TOS_DIR.

Updates and maintenance risk

Thinkorswim updates can replace its bundled JRE, launcher files, ARM browser libraries, or executable names. The script patches none of those files, but an update can still change the handoff behavior or remove java-arm. Rerun the verification after major updates.

This launcher is an unsupported compatibility workaround, not a Schwab-supported installation method. If Schwab changes install4j behavior or its Java requirement, revise or stop using it. Do not swap .install4j/jre.bundle, edit Info.plist, remove quarantine metadata, or re-sign the app.

How to revert or remove the changes

To revert, quit Thinkorswim and launch it normally from Finder. Move tos-native.sh to the Trash if you no longer want it; the script's variables are not persistent.

If Zulu JDK 17 was installed only for this launcher, first run /usr/libexec/java_home -V and ensure no other application needs it. Then remove only that JDK through Finder from /Library/Java/JavaVirtualMachines/, following Azul's macOS uninstall guidance.
